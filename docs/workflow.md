# Generate, log and verify

## Read only relevant inputs

Start with `program.md`, `state/block.json` and `state/recovery.json`. Lifting needs today's table, ramp/return, lift progression and `state/lifting.json`. Running/cycling needs endurance/run progression and `state/running.json`. Read assessment/adjustment rules when a test, plateau, decline, return or fatigue flag applies. Use `state/baseline.md` for initial calibration. Search specific comparable sessions in current logs; do not load old history routinely.

For bike sessions, include saved `cycling.equipment_settings` from running state. Preserve uncertain alternatives and the athlete's position labels; do not invent units or a machine identity.

Honor an explicit in-progress prescription freeze in block state. A slot's `pending_replacement` applies prospectively: reconcile the frozen session against its original exercise before activating the replacement and preserving the former record in `exercise_history`. If a later prescription comes first, keep any delayed old-exercise log separate; never relabel it as the replacement or overwrite the frozen logging table.

Apply the standing [readiness workflow](../program/readiness.md): assume good ordinary recovery unless contradicted, and generate/publish the next scheduled uncompleted workout after logging. This default supplies routine readiness for progression without inventing an observed recovery report; active injury, illness, return and fatigue restrictions still apply.

## Generate the workout

1. Resolve the requested date in America/New_York. Derive W1 onward from `calendar_anchor_date` (October 26, 2026), not the early activation date. October 25 is the authorized `Opening` Sunday leg session; earlier dates are Pre-block. After January 3, review before prescribing another block. Calendar rollover changes date fields, not stage or recovery clearance.
2. Use one state snapshot for both caches. Reconcile newer actual reports first. Apply symptoms/local restrictions and global recovery, using the athlete's ordinary recovery default unless contradicted → saved return/assessment limits → achieved stage/calendar ceiling → valid progression. Lowest limit wins. Resolve carried pace credit at its first eligible opportunity before new progression.
3. Calculate effective sets/dose after substitutions, omissions, cuts, trials and reductions. Current stage A with two bodyweight ab sets in M6/T7/L1 gives Mon/Wed/Thu/Sat/Sun **11/7/12/6/11 = 47** per regular week. Apply recovery state's exercise/load overrides, set ceilings and minimum RIR; stage advancement cannot remove these limits. The October 25 opening leg session has 11 sets separately; it does not replace Monday or establish a manageable week. The next regular Sunday is November 1; include the actual opening-session response in subsequent recovery decisions.
4. Give only effective work: slot, ordered exercise, sets, reps, load, RIR, rest; or exact endurance work/recovery/pace/effort. Matching lifts inherit previous working weights as authorized by the athlete. For `carried_unvalidated` loads, read the dated source and adjust to today's reps/RIR before prescribing; explain material changes. A carried 160 lb incline baseline is not evidence for 6–8 reps at that weight. Derive back-offs from today's effective top-set load and select Thursday's load independently. New/unmatched lifts require calibration to the rep/RIR target. Never invent completed weights.
5. Explain why this date/stage selects the workout. For each material hold/increase/reduction/omission show **dated same-slot actual → rule → decision**. Distinguish first exposure, historical non-comparable references and pending evidence. Unchanged rows may share one explanation.
6. Audit the adaptation: matching source date/setup, all required sets/effort, qualification count, recovery basis, stage/return/test eligibility, preserved local limits and no cancelled credit reused. Mark the athlete's recovery default as an assumption; other missing decision-critical evidence remains `pending`. Fix a mismatch before writing and record the correction.
7. Write daily and seven-day week caches using [dashboard.md](dashboard.md). After a session log, show the next scheduled uncompleted workout automatically. Label a future workout as a preview with its real date; keep live calendar and completed-session records unchanged. Build Watch files only for actually prescribed outdoor runs.

## Record actuals and decisions

- Lift: load/reps/RIR per set and slot. Run: each rep's average pace, final RPE, reported distance and any reported next-day recovery. Bike: minutes/effort. Symptoms: reported observations only. Use the standing good-recovery assumption for routine readiness; do not ask for routine recovery confirmation. Ask once for other decision-critical missing values; otherwise `n/r` in prose or null in JSON. HR/cadence and technique narration are not required.
- When a run’s shoe and distance are confirmed, add it to `state/shoes.json` once by session ID. Preserve estimated baselines and unresolved mileage; never add a planned run or an unconfirmed race twice.
- Shoe state v2 keeps separate records under `shoes`, with `active_shoes` and `last_used_shoe`. Preserve each pair’s own mileage basis and uncertainty; a first run in a new pair does not retire the old pair or transfer its mileage.
- Append dated `Hybrid v11 Wn` actuals to the relevant history stream (`Hybrid v11 Opening` for October 25). Store the effective prescription alongside actuals or reference its durable dated ledger entry; an overwritten cache must not erase what was prescribed. Record every heavy single exposure.
- Append numbered carried decisions to `history/adjustments.md`: source actuals, rule file/heading, previous → next dose/load, and pending gates. A hold cites the unmet gate. IDs increase after #429.
- Update relevant slot/run state and current-week outcomes. Completion can coexist with pending classification. Dashboard ranges/placeholders are not actual values; exact athlete-confirmed completions are acceptable.
- Follow the [readiness directive](../program/readiness.md) for ordinary missing recovery: use the documented good-recovery assumption rather than a pending/no-count result caused solely by silence. Completed normal ramp-week review can use the same recovery assumption with actual performance evidence. Missing evidence for an active injury, return or fatigue-observation restriction still holds its dependent decision; silence cannot clear it or diagnose fatigue.
- Count faster run reps toward progression when the other requirements pass. The pace check is one-sided: each rep must be no more than 5 s/mi slower than its prescribed target; there is no fast-side cutoff. Keep actual paces separate from the prescribed target used for streaks and next-dose decisions. Apply the October 30 directive in `program/run-progression.md`, not the superseded fast-rep exclusions in historical entries.
- Apply November 3's pace-first directive in `program/run-progression.md` after classification: use the slowest rep for a bounded 5–15 s/mi adjustment; comfortable effort can earn 5 after one hit, otherwise two comparable hits earn 5. Remove calendar speed waits, hold minutes on a faster target, and record source consumption before first changed exposure. A local upper-body maintenance hold alone is not a run restriction. State whether ordinary recovery was observed or assumed under the athlete's default; preserve other unresolved restrictions.
- At calendar week close, append outcomes, effective doses and manageable/recovery evidence to `history/weekly-summary.md`; retain unresolved gates. Do not mark unreported sessions done.
- After a lifting log or correction, refresh `lifting-history.json` from the dated actuals, preserving prior sessions and unique session/slot identities. Include performed set loads/reps/RIR and explicit skipped/substituted/unknown work; never use targets as actuals. This supplies the session history and same-slot “last time” references beside logging.
- Regenerate affected caches from reconciled state, including the next scheduled workout after a log. A duplicate/correction updates the existing session and next decision without another exposure or schedule advance; a backfill does not rewind an already valid upcoming workout. Parse JSON; verify dates, links, all effective sets/doses and adaptation evidence; persist state/logs/caches together. Verify publishing before claiming it succeeded.

## Compact state

`state/lifting.json` has all 33 named slots. Overlay each stored slot on `slot_defaults`, an explicit common empty record. Missing overrides inherit defaults; **never reset populated fields**. Prescription sets/reps/RIR/rest derive from day tables and active gates. Null load is uninitialized, including bodyweight/assisted slots until their convention is established.

At first exposure, store load/units, equipment/setup and per-hand/per-arm/assistance convention. `last_actual` points to a dated log. Maintain comparable first-set anchors, qualification/exposure counts, trial/cut state, decline cases and handled windows when relevant. Ab restrictions and temporary `slot_overrides` live in recovery state: preserve the baseline slot identity, render/log the effective exercise, and never transfer substitute performance into the baseline exercise's progression. Never borrow another slot's credit.

Carried loads use `load_status: carried_unvalidated` and a `load_source` key in `carryover_sources`. They are known prior working weights, not new-block actuals. Preserve source dates and ambiguous apparatus notation. Once an actual establishes the effective load in that slot, record it and change status to `established`; stage/progression gates still apply. `new_exposure_count` counts reported exposures, including ramp work; it is not qualification credit. Store temporary exercise actuals in `temporary_substitution`, leaving the baseline exercise’s load/ordinary progression state untouched. Do not reset established loads from the carry-over map on later reads. For an ongoing exercise replacement, preserve the former slot record under `exercise_history` before changing its active identity. Start the replacement’s actuals/exposure/qualification records independently; an athlete-requested starting load uses `load_status: prescribed_unvalidated` until performed. Never relabel the former exercise’s sets or copy another day’s credit.

Before return work, save pre-interruption reference, reason, initial/active limits and pending validation. Before fatigue reduction, save response dates, observation doses/evidence and effective normal-dose snapshot. Temporary work never erases return limits; repeated reduction never halves an already reduced prescription. Carried run awards retain source IDs/pace/minutes/format, assessment week, status and dated use/cancellation. Empty fields do not authorize reconstructing cancelled credit.

Adoption is once per stable block ID. Program version edits preserve actuals and migrate changed fields, never re-bootstrap. Result key `baseline-5k-reported-2026-10-24` is logged once. Future completed blocks may be archived verbatim with a small carry-forward.
